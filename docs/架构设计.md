# Pulse · 局域网 PC 硬件监控 — 架构设计

> 产品原则：**电脑端极简，手机端精致。**
> 电脑只负责「采集 + 供数」，手机负责「发现 + 展示 + 交互」。

## 1. 总体架构

```
┌─────────────────────────────  Windows 电脑端  ─────────────────────────────┐
│                                                                            │
│  monitor.exe（Go 静态编译，无窗口，~10MB，常驻内存目标 <25MB）                  │
│  ┌──────────────┐  ┌───────────────────────────────┐  ┌────────────────┐  │
│  │ 采集层 Collector │→│ 内存态快照 Snapshot（无数据库）      │←│ 采样器 1s 定时器   │  │
│  └──────┬───────┘  └───────────────┬───────────────┘  └────────────────┘  │
│         │ PDH / Win32 API / NVML   │                                      │
│  ┌──────┴──────────────────────────┴───────────────────────────────────┐  │
│  │ 服务层 :42710  HTTP GET /api/hello /api/snapshot   WS /api/ws (推送)     │  │
│  │         :42711/udp  发现应答（收 PULSE:DISCOVER:v1 → 回 JSON）           │  │
│  │ 鉴权：PIN 配对换取 Token → 后续请求携带 Bearer Token                      │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────┘
                      │ 局域网（无需互联网、无云、无账号）
┌─────────────────────────────  Android 手机端  ─────────────────────────────┐
│  Pulse App（Kotlin + Compose + Material 3 自定义设计系统）                    │
│  Discovery（UDP 广播 42711 + 手动添加兜底）                                   │
│  Connection（OkHttp WebSocket，断线重连 + Stale 判定 + 自适应降频）             │
│  UI：Devices 列表 ⇄ Dashboard ⇄ 详情页（CPU/GPU/内存/磁盘/网络）               │
│  图表全部自绘 Canvas（面积图/环形仪表/每核条/Sparkline），无重型图表依赖          │
└────────────────────────────────────────────────────────────────────────────┘
```

## 2. Windows Agent 技术选型（结论）

**Go 1.25 单静态二进制（`-ldflags "-s -w -H=windowsgui"`），零 CGO。**

| 维度 | 方案 A：Go + PDH/Win32（✅选定） | 方案 B：C# + LibreHardwareMonitorLib | 方案 C：Python + psutil |
|---|---|---|---|
| exe 体积 | ~8–12 MB | 自包含 ~70–90 MB | 需运行时或 PyInstaller ~20–40MB |
| 常驻内存 | ~10–25 MB | ~60–100 MB | ~40–70 MB |
| CPU 占用 | <0.5%（PDH 内核态直读） | ~1–3%（含驱动轮询） | ~2–5%（解释器 + psutil 轮询） |
| GPU 覆盖 | N/A/I 三家（WDDM 计数器）+ N 增强 | N/A 好，Intel 核显弱 | 依赖 WMI，最弱 |
| 温度/功耗 | 无驱动时有限（诚实返回 null） | 最好（但需内核驱动 WinRing0） | 差 |
| 杀软误报风险 | 低（无驱动、无注入） | 较高（WinRing0 口碑差） | 低 |
| 分发 | 双击即用 | 需 .NET 运行时或大体积自包含 | 需要解释器，最差 |

选择 A 的核心理由：**无内核驱动、无运行时、无杀软对抗**，满足「双击即用 + 极低占用」两条硬约束；代价是 CPU package 温度在部分机器拿不到——按「绝不伪造数据」原则返回 `null`，UI 显示「不支持」，README 说明如需深度传感器可后续加装 LHM 桥接模块（方案 B 作为可选扩展点，不进主链路）。

### 2.1 各指标采集路线（含 fallback）

| 指标 | 主路线 | 不可用时 | 备注 |
|---|---|---|---|
| CPU 使用率 | PDH `\Processor Information(_Total)\% Processor Time` | — | 每次 tick 采样，内核直读 |
| 每核使用率 | PDH `\Processor Information(*)\% Processor Time`（通配实例数组） | null | 实例名 `0,0`…`N` |
| CPU 频率 | PDH `\Processor Information(*)\% Processor Performance` × 基频 / `\Processor Frequency` | null | 有效频率 |
| CPU 温度 | PDH `\Thermal Zone Information(*)\Temperature`；连续采样方差≈0 判定不可信 → null | null | **无驱动时多数台式机拿不到，绝不伪造** |
| GPU 名称/总量显存 | DXGI `IDXGIFactory1::EnumAdapters`（vtable 直调） | null | 顺带拿 LUID 用于匹配计数器实例 |
| GPU 使用率 | PDH `\GPU Engine(*)\Utilization Percentage` 按 LUID 聚合（取引擎最大值，与任务管理器口径一致） | null | **跨厂商**（WDDM 2.x，Win10 1709+） |
| GPU 显存占用 | PDH `\GPU Adapter Memory(*)\Dedicated Usage` 按 LUID 匹配 | null | 跨厂商 |
| GPU 温度/功耗/频率 | NVML（`nvml.dll` 动态加载，NVIDIA） | null | 仅 NVIDIA；AMD/Intel 暂 null |
| 内存 | `GlobalMemoryStatusEx` + `GetPerformanceInfo`（Commit） | — | Swap 以 Commit 口径呈现并如实命名 |
| 磁盘容量 | `GetLogicalDriveStrings` + `GetDiskFreeSpaceEx` | — | 本地固定盘 + 可移动盘标记 |
| 磁盘活动 | PDH `\PhysicalDisk(*)\Disk Bytes/sec`、`% Idle Time` | null | |
| 网络速率 | PDH `\Network Interface(*)\Bytes Sent|Received/sec` | — | PDH 直接给出速率值 |
| 网卡信息/IP | `GetAdaptersAddresses`（筛 IPv4 私网 + 活动链路） | — | 与 PDH 实例名模糊匹配出「当前网卡」 |
| 系统信息 | 注册表 ProductName/DisplayVersion/UBR、`GetComputerNameEx`、`GetTickCount64` | — | 零 WMI |

PDH 结构体布局（`PDH_FMT_COUNTERVALUE_ITEM_W` 等）在首次运行时自校验：若格式化数值明显越界（usage<0 或 >100.5）自动降级为逐实例计数器模式。

### 2.2 设备发现

- **主路线**：Agent 监听 `0.0.0.0:42711/udp`；App 广播 `PULSE:DISCOVER:v1`（同时发 `255.255.255.255` 与本网段定向广播）；Agent 单播回 JSON 应答。**免 MulticastLock、不依赖 mDNS**，对 realme/小米等国产 ROM 的 mDNS 兼容性问题免疫。
- **兜底**：App 内手动添加（IP + 端口 + 可选 PIN）。
- mDNS/NSD 作为后续可选增强，不进第一版关键路径。

### 2.3 鉴权与安全（局域网个人工具的适度安全）

1. Agent 首次启动生成 6 位配对 PIN（写入 `status.json`，控制台/启动条也显示）与随机 Token、随机设备 ID（存 `config.json`）。
2. App 首连 → `401` → 提示输入 PIN → `POST /api/pair` → 返回长期 Token，App 存入 DataStore。
3. 之后所有请求 `Authorization: Bearer <token>`；WS 用 `?token=`。
4. 配对接口限速（每分钟 5 次）。Token 可在 `config.json` 重置。
5. 绑定默认 `0.0.0.0`（局域网工具必须），README 明确警告勿端口转发到公网；提供 `bindIP` 配置项可收紧。

### 2.4 断线与生命周期

- App 侧连接状态机：`Scanning → Connecting → Online → Stale(>5s 无消息) → Reconnecting(指数退避 1s→2s→4s→…→15s) → Offline`；UI 顶部状态徽标 + 数据卡片置灰并标注「最后更新时间」。
- Agent 写 `status.json`（供 start.bat 展示）+ 日志仅滚动 3 个 1MB 文件；无数据库、无磁盘轮询写入。

## 3. Android 端架构

```
ui/            DevicesScreen / DashboardScreen / DetailScreens / theme(自定设计系统) / charts(自绘)
data/          AgentRepository → DeviceConnection(OkHttp WS) + DiscoveryClient(UDP) + PairingApi
data/model/    Snapshot/Cpu/Gpu/Memory/…（kotlinx.serialization，全字段可空）
data/store/    DataStore：设备列表(名称/host/port/token)、主题模式
domain/        连接状态机 + 历史环形缓冲（内存 30min@1s = 1800 点，页离开即停）
```

- **性能红线**：1Hz 数据流不整页重组——快照按域拆分 `StateFlow`（cpu/gpu/mem/net 各一条 `derivedStateOf`），图表只重绘 Canvas；数值文本用 `fontFeatureSettings="tnum"` 等宽数字防抖动；App 退后台自动断开 WS。
- **自适应降频**：WS 下行控制消息 `{"ctrl":{"intervalMs":2000}}` 让 Agent 降采样（省电模式）。
- **主题**：Dark 优先设计（深石墨底、每指标专属低饱和色相 + 负荷语义色绿/黄/红），Light 同步派生；支持 System。

## 4. 数据协议

见 [数据协议.md](数据协议.md)。要点：全字段可空、协议带版本号 `v`、速率用字节/秒由手机端格式化、多 GPU/多网卡/多磁盘一律数组。

## 5. 端口与交付物

| 项 | 值 |
|---|---|
| HTTP/WS | TCP `42710`（config.json 可改） |
| 发现 | UDP `42711` |

## 6. Phase 8 长稳测试方案

- `tools/soak.ps1`：以 1Hz 记录快照到 JSONL，同时每 30s 采样 monitor.exe 的 CPU/内存/句柄数 → CSV。
- 会话内至少实测 1h（Agent + WS 客户端 + 手机端如已连接）；6h/24h 由脚本交付，判定标准：Agent 内存增幅 <10MB、无 WS 断流（心跳间隔>5s 视为断）、无明显句柄泄漏。
