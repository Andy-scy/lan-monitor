## 2. 采集 API 可靠性结论（关键证据）

- **CPU**：PDH `Processor Information` 计数器集（`% Processor Time`、`% Processor Performance`、`Processor Frequency`）有 `_Total` 实例，Win8+ 可靠，与任务管理器同源；`PERF_AVERAGE_BULK` 类型需要两次采样（已实现基线丢弃）。
- **CPU 温度**：`Thermal Zone Information(*)\Temperature`（PDH，单位开尔文）在**大量台式机不存在或返回恒定假值**（armtemp 项目明确记录 sentinel 行为）→ 必须做「恒定值判不可信」门控（已实现：45 样本窗口波动 ≥1.2℃ 才对外发布，否则 null）。不引入内核驱动就拿不到 package 温度是业界共识，显示 Unavailable 符合 Grafana/任务管理器惯例。
- **GPU（跨厂商）**：PDH `GPU Engine(*)\Utilization Percentage` 与 `GPU Adapter Memory(*)\Dedicated Usage` 是 **WDDM 层微软实现，与显卡厂商无关**，Win10 1709+ 全版本可用；实例名 `pid_N_luid_0x.._0x.._phys_N_eng_M_engtype_X`，任务管理器口径 = 每进程取最忙引擎值求和（已按此实现）。**PDH 无 GPU 温度公开计数器**（任务管理器走未公开 D3DKMT 通道）。
- **NVIDIA**：NVML `nvml.dll` 新驱动装在 System32（旧版在 `Program Files\NVIDIA Corporation\NVSMI`），普通用户可读；官方 go-nvml 是 CGO，**纯 Go `NewLazyDLL` 自写绑定是 coroot-node-agent、tkestack/gpu-exporter 等生产项目的成熟做法**。
- **AMD/Intel**：ADLX（偏 COM 风格）/IGCL（纯 C）理论可直调，但无公开 Go 绑定、无先行者，盲写风险高（Go 无法从原生崩溃恢复）→ v1 对其温度/功耗返回 null，用量/显存仍由 WDDM 计数器覆盖。
- **DXGI 注意**：第三方虚拟显示驱动（如本机实测的 GameViewer/Virtual Display）可能使 `CreateDXGIFactory1` 返回 E_NOINTERFACE → 架构上 DXGI 仅作「名称+显存总量」的首选来源，必须保留注册表显示类键（`DriverDesc`）兜底（已实现，实测命中）。

## 3. Go 生态

- **gorilla/websocket** 24.9k★ BSD-2：2022 归档、2023 复活，现活跃 ✅（选定）；备选 coder/websocket（5.5k★，context 风格）。
- mDNS：hashicorp/mdns 活跃，grandcat/zeroconf 停更 → v1 用 UDP 广播（见下），mDNS 留作后续增强。
- **x/sys/windows 无 PDH 封装**，参考 JeffAshton/win_pdh、jwenz723/pdh_exporter 自写（已实现并实测校准结构体布局）。

## 4. Android 端结论

- **图表**：Vico（3.2k★ Apache-2.0，日更）可做折线/面积，但环形仪表/每核柱/sparkline 仍需自绘；为统一视觉语言与零依赖风险，**全部自绘 Canvas**（`drawWithCache` 只重绘 draw 阶段，官方性能指南推荐路径）。
- **发现**：`255.255.255.255` 常被 AP 丢弃，必须发**子网定向广播**（DhcpInfo 推导）；收包需 MulticastLock；NsdManager/mDNS 在国产 ROM（realme/ColorOS/MIUI）上口碑差（mdnsd bug、省电静默丢弃）→ **主 UDP 广播、手动添加兜底**，与 Agent 侧设计互相印证。
- **性能**：状态流按域拆分 + `derivedStateOf`；Canvas 图表数据在 draw 阶段读取；WS 重连指数退避（1s→2s→4s…封顶 15s + 抖动）；DataStore 存设备列表。
- **UI 手法**（iStat/Stats/AIDA64/Trigone 共性）：大号等宽数字（Compose `fontFeatureSettings="tnum"` ✅）、单指标单色相 + 负荷语义色、环形仪表「当前值+峰值幽灵刻度」双层、每核柱状单 Canvas 一次画完、连接状态呼吸灯 + 断线图表冻结置灰。

## 5. 三方案终评（Windows Agent）

| 维度 | A. Go + PDH/NVML ✅ | B. C# + LibreHardwareMonitorLib | C. Python psutil |
|---|---|---|---|
| 体积 | **6.5MB 单 exe（实测）** | 70-90MB 自包含 | 需运行时 |
| 内存 | **~25MB（实测 25.2）** | 60-100MB | 40-70MB |
| 杀软风险 | 低 | 高（WinRing0） | 低 |
| 温度覆盖 | 热区温度（可信门控）+NVML | 最全（需驱动+管理员） | 差 |
| GPU 覆盖 | N/A/I 用量+显存全覆盖，N 温度/功耗 | N/A 好，Intel 弱 | 最弱 |
| License | MIT/BSD 无传染 | MPL-2.0 库引用可隔离 | GPL 风险 |
| 结论 | **选定** | 温度增强可选扩展点 | 否 |

> 方案 B 作为后续可选扩展点保留：如需风扇/每核温度/AMD 功耗，可增加「LHM 桥接模块」独立进程，主链路仍保持无驱动。
